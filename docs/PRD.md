## 1. 배경과 문제

할 일이 무엇인지는 알지만 시작을 못 하고 미루는 사람이 있습니다. 대표 사용자는 ADHD를 진단받고 약을 복용하는 20대 대학생 '지우'입니다.

지우가 막히는 지점은 두 단계입니다.

- **무엇을 할지 못 정한다**: 오늘 할 일을 구체적으로 적으려 해도 무엇을 적어야 할지 잘 떠오르지 않는다.
- **정해도 시작을 못 한다**: 정한 일이 막연하게 크게 느껴져 첫 손을 대지 못하고 미룬다. 하나에만 매달리다 다른 일을 놓치기도 한다.

그 결과 다음 날 밀린 목록을 보면 압도되어 앱조차 열기 싫어집니다.

## 2. 목표

- 앱에 들어오면 **오늘 할 일 3개**를 정하고, 그것을 반드시 끝낼 수 있게 만든다.
- 정한 3개를 **실행 가능한 서브 테스크로 쪼개**, 지금 당장 할 첫 걸음을 손에 쥐어준다.

## 3. 타깃 사용자와 핵심 흐름

### 3.1 타깃 사용자

| 항목 | 내용 |
| --- | --- |
| 이름 / 유형 | 지우 : 해야 할 일은 알지만 시작하지 않고 미루는 20대 대학생 (ADHD 진단, 약 복용) |
| 목표 | 하려고 마음먹었을 때 바로 행동하고 시작하고 싶다. |
| 동기 | 내 할 일을 빠르게 구체화하고 눈에 보이게 만들고 싶다. |
| 좌절 요인 | 하위 항목을 직접 쓰기가 귀찮다 : 계획을 세워도 지키지 못한다 |
| 행동 패턴 | 오늘 할 일 3가지를 적는다 : 하위 항목을 적고 싶지만 무엇을 적을지 막막하다 : 한 가지에만 매달리다 다른 일을 놓친다 : 밀리는 순간부터 리스트를 보면 압도된다 |

왜 대학생인가?: 
직장인처럼 하루에 정해진 업무가 없다는 점에서 무엇을 할지 더욱 알기 어려울 것이다.

**사용 맥락**

- **언제**: 기상 후 하루 할 일을 계획할 때 / 공부나 과제를 시작하기 직전
- **어디서**: 집 책상·침대, 도서관
- **왜**: 할 일을 잘게 나누면 무엇을 해야 하는지 명확해지고 시작을 이끌어낸다.

### 3.2 핵심 사용자 흐름

아침에 앱을 열어 **대화로 오늘 할 일을 정하고**, 막막한 일은 **서브 테스크를** 생성해서 오늘 정한 일은 무조건 끝내도록 해줍니다.

**진입 → 오늘 할 일 정하기 → 서브 테스크 생성 → 실행 → 재방문**

(각 단계의 상세 흐름과 기능은 아래 '5. 핵심 기능'에서 설명합니다.)

## 4. 핵심 개념: TODO Card

TODO Card는 사용자가 오늘 끝내기로 선택한 일을 나타내는 제품의 기본 단위다. 단순히 할 일을 기록하는 목록 항목이 아니라, 막연한 일을 시작하고 완료할 수 있도록 실행 과정을 담는 카드다.

카드에는 일의 제목과 진행 상태가 드러나며, 필요한 경우 AI와 함께 만든 서브 테스크와 예상 소요 시간, 사용자의 메모가 더해진다. AI는 내용을 제안하지만, 카드와 그 안의 실행 계획은 사용자가 확인하고 확정해야 반영된다.

사용자는 Today에서 카드를 보고 실행을 시작하며, 상세 화면에서 내용을 수정하거나 일을 다시 쪼갤 수 있다. 완료한 카드는 당일 진행 상황을 보여주고, 끝내지 못한 카드는 다음 날 자동 이월되지 않고 다시 선택할 수 있는 후보로 제안된다.

## 5. 핵심 기능

### 5.1 Today-todo

- 사용자는 정리되지 않은 생각을 채팅에 자유롭게 쏟아낸다.
- AI는 입력에서 실행 가능한 할 일 후보를 최대 10개까지 추출해 같은 채팅 안에서 보여준다.
- 사용자는 후보 중 오늘 할 일을 1~3개 직접 선택하고 확정한다. 세 개를 억지로 채우게 하지 않는다.
- 후보를 만들기 어려운 입력에는 AI가 구체적인 예시를 보여주고 다시 입력하도록 돕는다.

### 5.2 Subtask-split

- 사용자는 오늘 할 일을 확정한 직후 쪼갤 일 하나를 직접 고르거나 건너뛸 수 있으며, 카드 상세에서도 언제든 쪼개기를 시작할 수 있다.
- AI는 필요한 맥락만 한 번에 하나씩 최대 2~3번 묻고, 실행 가능한 서브 테스크를 5개 이하로 제안한다.
- 이미 쪼갠 일은 이전 대화와 완료 현황에 이어서 다시 쪼갤 수 있다.
- 더 쉬운 단계가 필요하면 전체 서브 테스크를 다시 생성하되, 새 결과는 사용자가 확정해야 기존 계획을 대체한다.

## 6. 스코프 (MVP)

**포함**

- Braindump → 후보 추출 → 최대 3개 선택
- AI 쪼개기(서브 테스크 5개 이하)와 '더 간단하게' 재생성
- 지난 쪼개기 대화 이어하기('다시 쪼개기')

## 7. 제품 원칙

- **압도하지 않기**: 대상 사용자(ADHD 성향)는 정보가 많으면 쉽게 압도된다. 할 일 후보·서브 테스크·밀린 목록을 한 번에 몰아서 보여주지 않는다. (오늘은 최대 3개, 서브 테스크는 5개 이하, 실행은 한 번에 하나)
- **질문은 꼭 필요한 만큼만**: 서브 테스크 생성 시 질문이 길어지면 이탈한다. 이미 명확한 항목은 건너뛰고, 선택지 형태로 최소한(2~3개)만 묻는다.
- **사용자가 결정하게 하기**: AI의 제안(후보·서브 테스크·예상 시간 등)은 사용자가 확정하기 전까지 실제 목록에 반영하지 않는다.
- **맥락을 잃지 않기**: 대화와 작성 중인 내용은 보존해 사용자가 중단한 지점에서 자연스럽게 이어갈 수 있게 한다.
