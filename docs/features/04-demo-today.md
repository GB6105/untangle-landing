> 요약: Today 실행 화면 — TODO Card 스펙·완료 체크·완료 연출·/register 소감 CTA 전환 — 데모 3단계(실행)와 종착 전환을 구현할 때 읽는다.

# Today 실행과 소감 전환

## 1. 목적

- PRD의 실행 단계를 데모로 재현한다: 확정한 TODO Card를 Today 화면에서 보고, 첫 단계·서브태스크를 체크하며 "시작하는 감각"을 체험한다.
- 체험의 가치 실감(첫 체크) 직후 `/register` 소감 CTA로 자연스럽게 전환한다 — 데모의 종착점.
- 재방문(다음날 재제안)은 완전 제외 — 다음날을 예고하는 문구·연출도 만들지 않는다.

## 2. 사용자 스토리

- '지우'는 자기가 고른 1~3장의 카드만 있는 조용한 Today 화면을 만난다. 방금 쪼갠 카드는 이미 펼쳐져 있고, "지금 할 첫 단계"가 눈에 들어온다.
- 안내 문장을 따라 첫 단계 하나를 체크하고, 작게 축하받는다.
- 그 순간 나타난 "소감 한 마디 남기기"를 눌러 방금의 경험을 남긴다. 더 해보고 싶으면 체크를 이어가도 된다.

## 3. 화면·인터랙션 명세

### 3.1 화면 구조 (`phase: today`)

- 헤더: 날짜 + "오늘 할 일 N개". 그 외 통계·스트릭·달력 없음.
- TODO Card 리스트 1~3장. **한 번에 한 카드만 펼침**(아코디언) — "실행은 한 번에 하나"(PRD 원칙 1).
- **도착 초기 상태(첫 행동 안내 — 필수 명세)**:
  - **방금 쪼갠 카드를 자동으로 펼친 상태로 시작**한다(쪼개기를 건너뛴 경우 첫 카드를 펼침). 한 번에 한 카드만 펼치므로 원칙 1과 충돌하지 않는다.
  - 펼친 카드의 **"지금 할 첫 단계" 블록을 시각적으로 포커스**한다(하이라이트 — 스크롤 최상단 노출).
  - 도착 시 Co-Planner 안내 1문장 표시: "이제 '지금 할 첫 단계' 하나만 체크해 보세요." (쪼개기를 건너뛴 경우: "오늘 할 일이 준비됐어요. 끝낸 일에 체크해 보세요.")
  - 근거: 첫 체크가 데모 성공 지표이자 소감 CTA 트리거(05 §3, 3.4)인데, 이 화면만 다음 행동 안내가 없으면 사용자가 조용한 화면 앞에서 멈추거나 이탈한다 — 펼치기→체크를 스스로 발견하게 두지 않는다.
- 하단에 작은 텍스트 버튼 "처음부터 다시 해보기"(상태 초기화 — 되돌리기 부담 제거). 확인 1회 후 초기화.

### 3.2 TODO Card 데모 스펙

- **접힘**: 제목 + 진행 표시 — **쪼갠 카드는 진행 배지(`2/5`)**, **미분해 카드는 완료 체크박스 하나**.
  - **쪼갠 카드에는 카드 레벨 완료 체크박스를 두지 않는다.** 완료는 서브태스크 전부 done으로만 판정한다(§4와 동일 기준). 카드 체크 한 번으로 서브태스크를 일괄 완료 처리하는 것은 "완료 체크를 시스템이 대신하지 않기"(원칙 3)와 충돌하므로 만들지 않는다.
- **펼침(쪼갠 카드)**: 상단 **"지금 할 첫 단계"** 하이라이트 블록(기존 스타일 재사용, 체크 가능) → 서브태스크 체크리스트(≤5) → 하단 "더 쪼개기" 텍스트 버튼(→ 03 §3.3 재진입 — 저장된 계획으로 result 화면을 재구성하고 항목별로 더 쪼갬. 이전 문답·완료 현황에 이어감 — 원칙 4).
- **펼침(미분해 카드)**: "막막하면 쪼개볼까요?" 한 줄 + 쪼개기 버튼(→ 03 §3.3 재진입 — clarify부터) + 카드 완료 체크.
- Today의 체크박스는 전부 "완료" 의미다 — split result의 "담을 항목 고르기" 컨트롤과는 시각 형태를 다르게 해 의미 혼동을 차단한다(03 §3.2와 쌍).
- 완료 체크를 시스템이 대신하지 않는다(원칙 3). 체크 해제도 자유(토글).

### 3.3 완료 연출 (절제 원칙 — 00 결정 10)

1. **첫 체크**(전 카드 통틀어 최초 1회 — firstStep·서브태스크·미분해 카드 체크 모두 해당): 체크 마이크로 애니메이션 + Co-Planner 한 줄 "방금 첫 칸을 채웠어요. 시작이 제일 어려운 건데요." 컨페티 등 과한 연출 금지.
2. **카드 완료** — 쪼갠 카드: 서브태스크 전부 체크(§3.2·§4와 동일 기준 — 카드 레벨 체크는 없음) / 미분해 카드: 카드 체크. 카드가 완료 상태로 전환 — 취소선이 아니라 채움/체크 애니메이션 + 따뜻한 1문장.
3. **전체 완료**(모든 카드 완료): 상단 완료 배너 "오늘 정한 일을 전부 끝냈어요" + 주 CTA. 다음날 이야기는 하지 않는다.

### 3.4 소감 CTA 전환 (전환의 핵심)

- **트리거: 첫 체크 1개.** 전부 완료를 요구하지 않는다 — 데모에서 실제 실행을 다 할 수 없고, 요구하면 이탈한다. "체크하는 감각"이 데모의 목적. (00 결정 5: 상시 노출 아님)
- 연출 시퀀스:
  1. 첫 체크 연출(3.3-1) 후 1.2초 뒤, 하단에서 완료 카드 **슬라이드업**(모달로 화면을 가로채지 않음).
  2. 완료 카드 내용: 체험 요약 3줄 — "쏟아낸 생각 → 오늘 할 일 N개 → 첫 걸음 완료" (자기가 만든 결과물이 소감 작성의 재료가 된다).
  3. Primary: **"소감 한 마디 남기기"** → `/register?from=demo`. 기존 `CtaButton`에 `href` prop을 추가한 뒤 재사용 — 현재는 `/register` 하드코딩에 label만 지원하므로 "무수정 재사용"이 아니다(00 §7 소폭 수정).
  4. Secondary(텍스트 링크): "조금 더 해보기" — 완료 카드가 **하단 고정 바로 축소**되어 소감 CTA 상시 유지(전환 기회를 잃지 않되 실행을 막지 않는다).
- 전체 완료 시(3.3-3) 완료 배너의 주 CTA도 동일 목적지.
- `/register`는 현행 유지 — 헤더 카피 "방금 함께한 첫 걸음, 어땠어요?"가 데모 완료 감정과 정확히 이어짐(확인). `from=demo` 쿼리는 로깅 구분용(05). `from=demo`일 때 닫기 X 목적지를 `/#experience`로 조정하는 것은 선택 사항(v1 생략 가능).

## 4. 상태·데이터

- 체크 상태는 `DemoCard.firstStep.done`·`subtasks[].done`·`done`에 반영, 전이마다 `untangle:demo:v1` 저장 — 이탈 후 재진입 시 완료 현황 복원(원칙 4).
- 첫 체크 여부는 cards에서 파생 가능(별도 플래그 불필요). 슬라이드업 1회성 노출 여부는 **`DemoState.slideupShown`**(00 §5에 정의 — 단일 출처)에 보관.
- 카드 완료 판정: **쪼갠 카드 = 서브태스크 전부 done**(firstStep은 보조 — 완료 판정에 필수 아님. 카드 레벨 체크는 존재하지 않음 — §3.2), **미분해 카드 = 카드 체크**.

## 5. 엣지 케이스

- 쪼개기를 건너뛰고 온 경우: 모든 카드가 미분해 — 첫 카드 자동 펼침(3.1) + 각 카드 펼침에서 쪼개기 유도(강요 없음).
- 체크 후 전부 해제: 슬라이드업은 재발동하지 않음(1회성 — `slideupShown`). 하단 바는 유지.
- `/register` 다녀온 뒤 `/demo` 재진입: today 상태 그대로 복원(01 문서).
- 카드 0개 상태로 today 도달: 정상 흐름상 불가 — 방어적으로 candidates로 되돌린다.

## 6. 구현 범위

- **포함**: Today 화면(헤더·카드 리스트·아코디언·도착 초기 상태와 안내 문장), TODO Card 접힘/펼침, 체크 인터랙션, 완료 연출 3종, 첫 체크 슬라이드업 + 하단 고정 바, `/register?from=demo` 링크(`CtaButton` `href` prop 사용), "처음부터 다시" 버튼.
- **제외**: 카드 편집·메모·예상 시간(부가 기능), 통계·스트릭, 다음날 재제안 관련 일체, `/register` 페이지 수정(쿼리 수신 로깅 외).
