# 데모 셸과 진입

## 1. 목적

- 랜딩 방문자가 부담 없이 전체 화면 데모(`/demo`)로 진입하고, 중단해도 맥락을 잃지 않게 하는 골격을 만든다.
- 데모의 전 단계(브레인덤프→선택→쪼개기→실행)가 이 셸 안에서 하나의 흐름으로 진행된다.

## 2. 사용자 스토리

- 랜딩에 온 '지우'는 첫 화면에서 "지금 바로 체험해보기"를 보고, 가입 없이 바로 시작할 수 있음을 알고 누른다.
- 스크롤 중 Experience 섹션의 프리뷰 카드를 보고 "직접 해보기"로 진입한다.
- 중간에 나가더라도(X·뒤로가기·탭 닫기) 다시 들어오면 "이어서 할까요?"를 만나 중단 지점부터 계속한다.

## 3. 화면·인터랙션 명세

### 3.1 `/demo` 라우트 구조

- `app/demo/page.tsx`: 서버 컴포넌트 셸 — `metadata` export(제목: "체험 — Untangle" 류) + 헤더 + `DemoFlow` 클라이언트 컴포넌트. 삭제된 `app/split/page.tsx`의 검증된 패턴 준용: `min-h-dvh`, `max-w-[480px]` 단일 컬럼(랜딩·`/register`와 동일 앱 셸).
- `components/demo/DemoFlow.tsx`("use client"): phase 오케스트레이터(`useReducer`), localStorage 복원/저장 담당.
- 헤더 구성: 좌측 로고(소형) + `데모` 배지 / 중앙 **진행 점 3개**(①정하기 ②쪼개기 ③실행 — 현재 단계만 채움) / 우측 닫기 X.
  - 진행 점은 "짧게 끝난다"는 안심 신호. 숫자 카운터·타이머·퍼센트 금지.
  - 쪼개기를 건너뛰면 ②점은 건너뛴 상태(흐림)로 ③으로 진행.

### 3.2 진입점

1. **Hero 직하 Primary CTA (신설)** — 현재 `sections/Hero.tsx`에는 CTA가 없다(확인).
   - 버튼: **"지금 바로 체험해보기"** → `/demo`. 보조문구: "가입 없음 · 머릿속을 쏟아내는 것부터 시작해요".
   - 근거: above-the-fold 행동 요청 부재는 이탈 요인. "가입 없음"으로 진입 장벽 제거.
   - **시간 약속 금지**: "3분" 등 검증 가능한 소요 시간 카피는 쓰지 않는다 — 표준 경로 상단이 3분을 넘을 수 있고(00 §2 재산정), 약속 위반은 ADHD 타깃에게 이탈 요인. "짧게 끝난다"는 안심은 진행 점 3개(3.1)가 담당한다.
2. **Experience 섹션 프리뷰 카드 (기존 인라인 SplitChat 대체)** — 아래 3.3.
3. FinalCta 직전 보조 진입점(미체험 스크롤러용)은 v2 선택 사항. FinalCta의 소감 CTA는 체험자용으로 그대로 유지(역할 분리).

### 3.3 Experience 섹션 전환 (진입점화)

- 인라인 `SplitChat`(실동작 LLM 채팅)을 **스크립트 프리뷰 카드 + 진입 CTA**로 교체한다. 결정 근거는 `00-overview.md` 결정 4-2 참조.
- 프리뷰 카드 스펙:
  - Co-Planner 채팅 카드의 시각 언어(헤더·말풍선) 유지. 배지 텍스트는 "쪼개기" → "오늘 정하기".
  - 내용: "쏟아내기 → 오늘 할 일 고르기 → 첫 단계 받기"를 보여주는 스크립트된 대화 연출. v1은 정적 스냅샷(LLM 호출·타이핑 애니메이션 없음)으로 충분, 15~20초 루프 애니메이션은 v2 선택. (`origin/feat/daily-top3`의 ec5531b "오늘의 계획 프리뷰" 커밋이 정적 프리뷰 전례 — 확인)
  - 카드 전체 탭 가능 + 하단 버튼 "직접 해보기" → `/demo`. 카드 안 모조 입력창을 탭해도 즉시 `/demo` 브레인덤프 화면으로 전환(입력 의도를 잇는다).
  - 섹션 하단의 기존 소감 `CtaButton`은 체험 진입 CTA로 교체 — `CtaButton`에 `href` prop을 추가한 뒤 `href="/demo"`로 사용(현재는 `/register` 하드코딩 — 00 §7 소폭 수정). 체험 전 방문자에게 소감 CTA는 시기상조 — 소감 CTA는 FinalCta에 유지.
  - `sections/Experience.tsx`에 `id="experience"` 앵커 부여(데모 종료 복귀 목적지).
- **이어서 하기 상태**: `untangle:demo:v1`이 존재하고 `cards`가 있으면 프리뷰 카드 하단 문구를 "만들던 오늘 할 일이 있어요 — 이어서 하기"로 교체(클라이언트 소형 컴포넌트, 마운트 후 판정).

### 3.4 상태 복원 (재진입·새로고침)

- `/demo` 마운트 시 `untangle:demo:v1` 복원 시도:
  - 저장 상태 없음 → 브레인덤프 웰컴부터 시작.
  - 저장 상태 있음(braindump 원문 이상 진행) → "이어서 할까요, 처음부터 할까요?" 선택 1회 제시. [이어서 하기] = 저장된 phase로 복귀 + 요약 안내 1문장, [처음부터] = 상태 초기화.
- 대화 로그는 저장하지 않으므로(00 §5) 복원 화면은 현재 phase의 결과물(후보/카드)과 안내 문장으로 재구성한다.

### 3.5 중도 종료(X) UX

- X는 우상단 상시 노출(`/register`와 동일한 위치·아이콘 관성).
- **결과물이 없는 시점**(카드 확정 전): 확인 없이 즉시 종료 → `/#experience`. 잡는 모달은 압도하지 않기 원칙 위배.
- **결과물이 생긴 시점**(카드 확정 이후): 가벼운 바텀시트 1회만 — "지금까지 만든 오늘 할 일은 저장해둘게요" + [이어서 하기] [나가기]. 나가기를 막지 않는다. localStorage에 실제로 저장되므로 카피는 진실.
- 종료 후 Experience 프리뷰 카드가 "이어서 하기" 상태로 표시(3.3).

## 4. 상태·데이터

- `DemoState`/저장 키/리듀서 방침은 `00-overview.md` §5가 단일 출처(04의 슬라이드업 1회성 플래그 `slideupShown` 포함). 이 문서 범위는 복원·저장 타이밍(마운트 후 복원, 상태 전이마다 저장)과 종료 동선.

## 5. 엣지 케이스

- localStorage 접근 실패(프라이빗 모드): 저장 없이 진행 — 데모 자체는 동작, 이어하기만 불가.
- 스테일 상태(예: 오래 전 저장분): v1은 만료 정책 없음 — "처음부터" 선택지가 해소 수단.
- `version` 불일치: 상태 폐기 후 새로 시작.
- API 키 미설정 환경: `/demo` 진입 자체는 막지 않고 제출 시점에 에러 배너(05 문서 방침).
- 딥링크(`/demo` 직접 진입): 저장 상태 없으면 브레인덤프 웰컴부터. 로깅 source는 "direct".
